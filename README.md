# tryon-dm-bot

بات Try-On برای دایرکت اینستاگرام (نسخه اولیه برای پایلوت)

## جریان کار
1. اینزی (یا خود پیج) عکس لباس را می‌فرستد ← بات آن را (Echo) ذخیره می‌کند.
2. مشتری متن `TRIGGER_TEXT` (پیش‌فرض: «پرو لباس») را می‌فرستد ← بات عکس می‌خواهد.
3. مشتری عکس می‌فرستد ← کار وارد صف می‌شود ← Try-On ← نتیجه در همان چت ارسال می‌شود.
4. عکس مشتری بلافاصله پاک می‌شود؛ بقیه فایل‌ها بعد از `FILE_TTL_HOURS`.

## اجرا (Node 20.6 یا بالاتر)
```
npm install
cp .env.example .env              # مقادیر را پر کن
cp pages.json.example pages.json  # توکن پیج را بگذار
npm start
```
برای تست محلی یک آدرس HTTPS عمومی لازم است (مثلاً `ngrok http 3000`) و همان را در `PUBLIC_BASE_URL` و Callback URL وبهوک بگذار: `https://ADDRESS/webhook`

## pages.json
کلید هر پیج همان `entry.id` است که در وبهوک می‌رسد. اگر نمی‌دانی چیست، یک پیام تست بفرست؛ بات در لاگ می‌نویسد
`Unknown entry.id (add it to pages.json): ...` ؛ همان عدد را با توکن بگذار.

## حالت mock
با `TRYON_PROVIDER=mock` بات عکس خود مشتری را برمی‌گرداند. فقط برای تست کل مسیر (دریافت پیام، Echo، صف، ارسال عکس) است.
بعد از انتخاب سرویس Try-On، تابع `runTryOn` را در `src/tryon.js` و تابع `classifyGarment` را کامل کن.

## محدودیت‌های این نسخه
- صف و وضعیت‌ها در حافظه/فایل JSON‌اند (برای ۶ پیج کافی؛ برای مقیاس بزرگ‌تر Redis و Postgres).
- تشخیص دسته لباس هنوز ثابت است (`DEFAULT_CATEGORY`).
- کنترل کیفیت نتیجه و تلاش مجدد اضافه نشده است.
- فقط روی متن دقیقاً برابر با `TRIGGER_TEXT` فعال می‌شود.
